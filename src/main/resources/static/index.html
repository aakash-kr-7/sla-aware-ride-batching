    Local Environment Startup Guide

    From the project root, start the local PostgreSQL container, then launch the Spring Boot service:

    docker compose -f compose.local.yml up -d --wait

    Launch the application with the fixtures profile:

    # Windows PowerShell:
.\mvnw.cmd spring-boot:run '-Dspring-boot.run.profiles=local-fixtures'

# Linux / macOS:
./mvnw spring-boot:run -Dspring-boot.run.profiles=local-fixtures

    Open http://127.0.0.1:8080/ for this console or http://127.0.0.1:8080/swagger-ui/index.html for Swagger UI. To reset database state, stop the application and run docker compose -f compose.local.yml down --volumes.

    Architecture & Batching Optimization Pipeline
    Client / Swagger UI JSON Requests + Bearer JWT
    →
    Spring Boot 3 Core Auth · Ingestion · Planner · Dispatch FSM
    →
    PostgreSQL 16 ACID State · Row Locks · Invariants

    Optimization Pipeline Stages:

    1. Window Collection: Claims eligible pending bookings within 15-minute half-open UTC windows [t_start, t_end). Urgent bookings within 20 minutes can be released early.
    2. Spatial Partitioning: Partitions requests by pickup zone and direction vector to prune search space before routing.
    3. Feasible Insertion Search: Evaluates stop permutations, checking 3 hard constraints: peak vehicle occupancy (≤ 4 seats), pickup SLA deadlines (≤ 20 min), and maximum detour ratio.
    4. Transactional Dispatch: Persists planned routes and creates driver offers. Acceptance re-verifies route feasibility under database row locks.

    ETA calculations use local Euclidean distance with circuity factors and dwell times. No third-party mapping dependencies required.
